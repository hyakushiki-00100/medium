# 制作フロー

企画から公開、振り返りまでの標準フローです。各作品は必ずこの流れに沿って進めます。

## 全体像

```
① 企画      → ② 承認      → ③ 執筆
                                  ↓
⑦ 振り返り  ← ⑥ 公開      ← ⑤ 修正 ← ④ レビュー
```

## 各ステップ

### ① 企画
- [`templates/proposal.md`](../templates/proposal.md) をコピーして企画書を作成する
- テーマ・読者ターゲット・伝えたい価値・想定文字数を明記する
- 企画は「1作品 = 1企画書」で管理する

### ② 承認
- 週次の企画会議、または非同期レビューで担当編集が承認する
- 承認基準: 読者価値が明確 / 既存作品と重複しない / 現実的な工数
- 承認されたら担当ライターと締切を決める

### ③ 執筆
- [`templates/article.md`](../templates/article.md) をコピーして [`works/drafts/`](../works/drafts/) に配置する
- ファイル名は `YYYYMMDD-slug.md`（例: `20260724-medium-workflow.md`）
- 執筆中は本文冒頭のメタ情報 `status: draft` を維持する

### ④ レビュー
- 執筆者以外の1名以上がレビューする
- 観点: 構成 / 事実の正確さ / 読みやすさ / [スタイルガイド](style-guide.md)準拠
- 指摘はコメントとして残し、致命的な問題があれば③に戻す

### ⑤ 修正
- レビュー指摘を反映する
- 反映後、レビュアーが再確認して合意する

### ⑥ 公開
- [`docs/publishing-checklist.md`](publishing-checklist.md) をすべて満たすことを確認する
- Medium に公開し、メタ情報を `status: published` に更新、公開 URL を追記する

### ⑦ 振り返り
- 公開後1〜2週間で反応（閲覧数・反応・コメント）を確認する
- 学びを次の企画に活かす

## 状態管理

各作品の状態はファイル冒頭のメタ情報で管理します。

| status      | 意味                     |
|-------------|--------------------------|
| `draft`     | 執筆中                   |
| `review`    | レビュー中               |
| `revising`  | 修正中                   |
| `published` | 公開済み                 |
