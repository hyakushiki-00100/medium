# 記事制作標準（ボリューム・構成・カバー）

禅語シリーズで実証した制作標準。新記事はこの基準に揃える。
執筆方針の全体像は [`../.claude/agents/article-writer.md`](../.claude/agents/article-writer.md)、
非交渉の品質基準は `CLAUDE.md` を参照。

> ⚠️ **適用範囲**: 本ドキュメントは禅宗（中国禅・日本の臨済宗/曹洞宗）由来の語を扱う**禅語シリーズ**を
> 前提に書かれている。禅語シリーズ以外（例: 天台宗・浄土宗など禅宗に限らない仏教の言葉を扱う
> **仏教語シリーズ**）は、ペルソナ・ボリューム目安・構成の型・史実性への誠実な姿勢はそのまま踏襲しつつ、
> カバーのラベル文言・アクセントカラーは**シリーズごとに差別化**する
> （`tools/build_covers.py` の `BUDDHIST_ACCENT_COLOR` / `JOBS_BUDDHIST` を参照。カバー画像仕様の節も参照）。
> シリーズの切り分けと経緯は [`../articles/tag-tracker.md`](../articles/tag-tracker.md) の
> 「仏教語シリーズ」節、[`../articles/note/README.md`](../articles/note/README.md) の同節を参照。

> ⚠️ 内部運用ドキュメント。確からしさが不確かな項目は「要確認/未検証」と明示する。
> ただし**記事本文には確信度ラベルを残さない**（読者向けは地の文で表現）。

## 話者ペルソナと語彙（英語・日本語 共通・最優先）

記事の語り手は、次の一貫したペルソナとして書く。**英語も日本語も、このペルソナが選ぶ語彙で書く。**

- **話者ペルソナ**: 40 代の男性、英語ネイティブ、高所得・高学歴。広く読書し複数分野に通じた、洗練された professional。知的だが衒学的（見せびらかし）でない。落ち着いた自信。
- **英語（Medium）**: 日本語を訳さない。**ネイティブが実際に使う語彙・イディオム・リズムで直接書く**（translationese を排除）。
  教養ある大人の register——精確・抑制的・簡潔。硬い逐語訳構文、和文脈の直訳、不自然なコロケーションを避ける。
  比喩・文化的言及は西洋の読者にそのまま通じるものを選ぶ。
- **日本語（note）**: 同じペルソナの感覚で語彙を選ぶ。**教養ある落ち着いた知的な文体。** ただし note の可読性（短い段落）は維持。
  稚拙な言い回しも、英語からの直訳臭も避ける。
  **em dash（——）を多用しない。** 英語版のリズム（`—…—` で挟む同格・言い換え）をそのまま日本語に持ち込むと
  翻訳調で読みにくくなる。読点・括弧（　）・文の分割（。で切る）に置き換える。目安は1記事あたり2〜3箇所まで。
- **翻訳臭の具体的なチェックポイント**（kissako-ja.md の「カテゴリー」指摘（2026-08-08）から追加）:
  - **不要なカタカナ借用語を使わない。** 英単語をそのままカタカナに置き換えただけの語（例:「カテゴリー」）は、
    同じ概念を指す和語・漢語がすでに本文にあるなら特に浮く。1本の記事の中で同じ概念に複数の語（例:
    「型」と「カテゴリー」）を使い分けない。書き終えたら、その記事で最も多く使っている具体語（型・仕分け・
    レッテル 等）に統一し直す。
  - **直訳臭のあるコロケーションを避ける。** 「調整を拒む」（refuse the calibration の逐語訳）、「劇的な形で」
    （in dramatic fashion の逐語訳）、「基本的なもてなし」（basic hospitality の逐語訳）のような、英語の
    語順・修飾関係をそのまま持ち込んだ組み合わせは、日本語として不自然でも意味は通ってしまうため見逃しやすい。
    声に出して読み、和語として自然かを確認する。
  - **英語の体言止め・断片文をそのまま日本語の述語なし文にしない。** 英語のリズム重視の断片（"a ten-year
    veteran doing X, a new hire who's done it elsewhere" 型）を、動詞を欠いた日本語の羅列に変換すると
    翻訳調になる。日本語では述語を補って自然な文にする。
  - EN を書き終えたあとに JA を書く場合でも、**EN の文を頭の中で置き換えながら訳さない。** 同じ事実・同じ
    ビートを、日本語のネイティブが最初から日本語で考えたときの語順・語彙で書き直す。仕上げに一度、
    通しで音読して「翻訳された文章」に聞こえないか確認する（EN 側の QA 観点と対になる確認）。
- **共通の土台（不変）**: CLAUDE.md の Voice（calm / practical / secular、二人称 "you"、誇大・神秘化・恐怖訴求をしない）は維持。
  本ペルソナはその範囲内での register 指定であり、上書きではない。

> 検証観点（QA）: EN は「翻訳された文章」に読めないか（translationese の兆候＝逐語的な接続、不自然な語順、和製比喩）。
> 日英とも、40 代・高学歴ネイティブが書いたと感じられる語彙選択になっているか。

## 脚注スタイル（人名・用語の付随情報）（オーナー指示・2026-08-13〜）

人名・書名の**読み仮名・生没年・成立年・用語の定義**など、地の文の理解に必須でない付随情報は、
本文中に丸括弧で埋め込まず、**脚注に切り出す**。mu（無字）で導入、以降の新規記事から標準。

- **EN**: 本文には上付き数字（¹²³…Unicode）だけを付す。例: `Zhaozhou Congshen¹`。
  記事末尾、`---` の直後・Sources 行の直前に脚注リストを置く。例:
  ```
  ¹ Zhaozhou Congshen (趙州従諗): 778–897.
  ² Wumen Huikai (無門慧開): 1183–1260.
  ```
- **JA**: 本文には全角アスタリスク＋番号（＊1＊2…）を付す。例: `趙州従諗＊1`。
  水平線（──────────）の直後・「主な参考」行の直前に脚注リストを置く。**脚注本文には読み仮名だけでなく
  元の漢字も必ず併記する**（オーナー指示・2026-08-13）。例:
  ```
  ＊1 趙州従諗(じょうしゅうじゅうしん)。778〜897年。
  ＊3 無門関(むもんかん)。
  ```
- **本文に残すか脚注に送るかの判断基準**: その数字・読みが**その文自体の論旨に使われているか**で判断する。
  例えば「A は B より◯年古い」という比較そのものが論旨なら、比較に必要な数字は本文に残し、
  読み仮名や重複する属性だけを脚注に送る（mu-en の "compiled decades before Wumen's case" のように、
  比較の結論は地の文に残し、生没年の実数値だけを脚注に落とす）。単なる人物特定のための生没年・読み仮名は
  丸ごと脚注へ。
- Sources／主な参考 の引用文自体はこれまで通り本文末尾の別ブロックに残す（脚注ブロックとは別）。
- **既存の公開済み・未公開記事は遡って変更しない**（mu 以降の新規記事にのみ適用）。

## 見出しの使い回しを避ける（EN・JA 共通）

「Where this lands at work」「仕事で刺さる瞬間」のような**定型見出しを毎回使い回さない**。
シリーズを通して読む読者に「またこの型か」と気づかれ、記事ごとの切り口の独自性を薄める。

- **各記事の見出しは、その記事固有の核心語・比喩から作る**（例: kankyakka なら「足元」、byojoshin なら「向かう」）。
- 執筆前に既存記事の見出し一覧をざっと確認し（`grep -n "^## " articles/medium/*.md`）、既出の言い回しと重複していないか確かめる。
- ビートの役割（仕事への応用・内面への応用・史実性の断り 等）は共通でよいが、**見出しの文言は記事ごとに変える**。

## 定型文の使い回しを避ける（センテンス単位・EN/JA 共通）（2026-08-15〜）

見出しだけでなく、**ビートの導入・締めに使う一文の構文そのもの**が記事をまたいで無意識に使い回され、
複数回の Opus 精査・オーナー確認で繰り返し指摘されている。執筆前・執筆後にこのリストと照合し、
新しい記事で同じ構文を使っていないか確認する。見つかったパターンは追記していくこと。

**EN — 確認済みの使い回し（3 記事以上で発生）**:
- `"[Teacher] never told [X]..."` を締めのビートで使う（anjin / hogejaku / kyogen / muichimotsu）。
- 文頭 `"Worth being honest/precise about..."` など、史実性ビートを `Worth ~ing` で始める（anjin / baishijukuya /
  hogejaku / ichigoichie / ichigu / katsu / kissako / masangin / muichimotsu の 9 本）。
- `"None of this argues for X. It argues for checking whether Y"` / `"None of this is an argument for/against X.
  It's a distinction between..."`（kankyakka / kissako / muichimotsu / mukudoku / sekishu / shujinko）。
- `"Turned inward," / "Turned toward yourself," / "Turned on yourself,"` を内面ビートの書き出しに使う
  （muichimotsu / kissako / baishijukuya）。
- 由来ビートを `"The teacher was X, a disciple of Y..."` で始める（fusaku / kissako / masangin / daichi / kanto）。
- `"There's a version of this..."` を内面ビートの書き出しに使う（byojoshin / ichigoichie / ichigu / kankyakka /
  kissako / mukudoku）。
- `"The same [名詞] runs/shows up privately"` を内面ビートの書き出しに使う（mu / daichi）。
- `"There's a private version/edition/shape of..."` を内面ビートの書き出しに使う（mukudoku / sekishu / nittensuishu）。
  nittensuishu で検知・回避（2026-08-27、内容を直接書き出す形に変更）。
- 見出し `"What [X] actually [Y]"` 型（masangin / muichimotsu / ukiseikou）。
- 見出し `"The [名詞] you [動詞] yourself"` 型（katsu「The shout you give yourself」/ mu「The certainty you
  manufacture for yourself」/ mukudoku「The ledger you keep on yourself」）。
- 見出し `"A caveat about the record"` 系（hogejaku / katsu / kissako / muichimotsu で衝突歴あり）。
- 史実性ビートの締め `"What's certain is that ... [N] hundred years ..."`（bashoan / hifuhiban）。
  fact-checker（Opus）で検知・回避（2026-08-17）。

**JA — 確認済みの使い回し**:
- `「〜ではありません。むしろ、〜」`（英語の "It's not X. It's Y" の直訳的パターン）を転換の一文に使う
  （kyogen / kyokasuigetsu / masangin / muichimotsu / nengemisho の 5 本、houu・un にも緩い変種あり）。
  kanto でオーナーから指摘（2026-08-15）。代わりに、同じ転換を「〜であれば、ここで終わっていたはずです。
  実際に続くのは〜だからです」のような、否定→肯定ではない構文で表現する。
- `「彼は…必要がなかったのです。」` 系の結び（kissako / muichimotsu / baishijukuya）。
- 由来ビートの書き出し `「答えたのは X＊1。〜の弟子(法嗣)で」` / `「この言葉を語った師は X＊1。〜の弟子であり」`
  型（kanto / nichinichi / muinoshinnin / daichi の 4 本）。mukansho で検知・回避（2026-08-17）。
- 内面ビートの見出し `「自分自身に〜」` 型（mu「自分自身に対して作り出す確信」/ mukudoku「自分自身につける帳簿」/
  muinoshinnin「自分自身に、こっそり割り当てている位」の 3 本）。mukansho で検知・回避（2026-08-17）。
- 結びの文末 `「〜ただけでした。」`（kanto / daichi / nichinichi / anjin / hifuhiban の 5 本）。
  fact-checker（Opus）で検知・回避（2026-08-17）。
- 内面ビートの書き出し `「同じ[名詞]は、もっと個人的な場面にも{現れます/起こります/働きます/姿を現します}」`型
  （bashoan / daichi / kanto / mu / mukanjo の 5 本）。nittensuishu で検知・回避（2026-08-27、
  メタな前置きの一文を削除し内容を直接書き出す形に変更）。

見出しと同様、**執筆前に `grep -n "^## " articles/medium/*.md` に加えて、上記のセンテンス断片で
`grep` して既出でないか確認する**（例: `grep -rn "Worth being" articles/medium/*.md`）。
それでも書いてしまった場合は、Opus 精査やオーナー確認を待たず自分で検知し、書き直すこと
（このセッションでは複数記事で執筆直後の自己チェックにより実際に検知・修正できている）。

## 標準制作フロー（着手指示で一気通貫・自動実行）

「次のネタ〈禅語〉で着手」等の指示を受けたら、以下を**まとめて自動実行**する（各ステップで逐一確認を取らない）。

1. **執筆(英語＋日本語)** — 英語=Medium(`articles/medium/<slug>-en.md`)、日本語=note(`articles/note/<slug>-ja.md`)。
   8ビート構成・史実性の誠実な明記・**確信度ラベルゼロ**。語数/字数は**コードで検証**(EN ~720–750 words / JA ~1,900–2,100 字)。
   **語彙・文体は上記「話者ペルソナ」に従う**(EN は日本語の翻訳ではなくネイティブの語彙で直接執筆＝translationese 排除)。
   **Medium 版 front matter には `title` に加えて `subtitle` も生成する**(2026-08-13〜)。
   このシリーズのタイトルは「フック文(1〜2文)。The Zen Word/Story/Koan/Rule/Answer "X" (漢字).」という型が定着しているため、
   後半の識別部分(`The Zen ... "X" (漢字).`)を `subtitle` フィールドに切り出す。Medium 投稿時は Title 欄に `title` からその末尾の
   識別部分を除いたフック文のみ、Subtitle 欄に `subtitle` フィールドの値をそのまま貼る。識別部分が無い変則タイトル(コロン区切り等)は、
   コロン/ダッシュの前後で機械的に分割してよい。過去記事(anjin まで)は `subtitle` フィールドを追記済み。

   **タイトルの長さに上限を設ける**（2026-08-17〜）。mukanjo→bashoan→suikogyu の3記事で、
   フック文に問答のやり取りを丸ごと詰め込む書き方が定着し、タイトルが記事ごとに単調増加していた
   （JA: 96字→116字→127字、EN: 26語→36語→42語。オーナー指摘・2026-08-17）。
   これはフック文に「一問一答」ではなく「二往復・三往復の問答」を丸ごと収めようとしたことが原因。
   **目安は JA 70〜90字・EN 24〜32語**（kanto〜muinoshinnin の実績値に基づく）。
   フック文は問答の**核心の一往復**（最も強い一言）だけに絞り、背景の問い・経緯は本文の冒頭で語る。
   執筆後にタイトルの字数・語数をコードで確認する:
   ```bash
   # JA タイトル文字数
   python3 -c "import re;t=open('article-ja.md').read();m=re.search(r'^title: \"(.+)\"',t,re.M);print(len(re.sub(r'\s','',m.group(1))))"
   # EN タイトル語数
   python3 -c "import re;t=open('article-en.md').read();m=re.search(r'^title: \"(.+)\"',t,re.M);print(len(re.findall(r\"[A-Za-z']+\",m.group(1))))"
   ```

   **検索流入を意識したタイトル・見出し設計**（オーナー指示・2026-08-17〜、新規記事から適用。
   既存の公開済み記事は遡って直さない）。専任の SEO エージェントは置かない
   （Medium はタグ・Publication 経由の内部流入が主で、キーワード調査ツールも無いため）。
   代わりに、事実確認の WebSearch ついでに以下を確認し、タイトル・見出しに反映する軽量な運用とする。
   - ネタ調査の WebSearch 時に、その禅語・公案が英語圏で何と呼ばれているか（例:
     "Nanquan Kills the Cat", "the water buffalo koan" 等）も併せて見ておく。
     EN タイトルの識別部分（`The Zen Case "X" (漢字).`）は、その定訳・通称に寄せる
     （造語的な言い換えを避ける）。
   - JA タイトルの正式名・読みは、既存の複数サイトで実際に使われている表記・ふりがなと一致させる
     （mukanjo の「むかんしょ」→「むかんじょ」訂正のように、自己流の読みを避ける）。
   - 見出し（`## `）は本文の要旨を検索可能な語で表す（比喩だけに寄りすぎない）。
     見出しの使い回し回避ルール（既出）と両立させる。
   - タグ設計（`tag-strategist`）は既存どおり Medium 内の発見性（タグ・Publication）を担当。
     本項目はそれに加えて、Google 等の外部検索からの流入も見込んだタイトル表記の一致を狙うもの。
2. **カバー生成** — `python3 tools/build_covers.py <slug>`（JOBS に slug 追加）。**正式名を優先**（崩れれば字サイズ/字間で調整）。
3. **タグ付け** — Medium 5 タグ（1 つ目最重要・固定ペア Self Improvement / Mindfulness・広リーチ＋ニッチ）を設計し、
   `articles/tag-tracker.md` と各記事 front matter に記録。note 版は日本語ハッシュタグを front matter に。
4. **インデックス更新** — `articles/note/README.md` / `articles/covers/README.md` / `tag-tracker.md`。
5. **ファクトチェック（自動・オーナー指示・2026-08-17〜）** — commit の前に、`fact-checker` エージェント
   （`.claude/agents/fact-checker.md`、model: opus）を**必ず呼び出す**。EN/JA 記事本文と front matter の
   `source:` を渡し、出典の前後関係・引用の逐語性・断定過多・定型文衝突を再検証させる。
   これは毎回自動実行するステップであり、「Opus で精査して」という指示を都度待たない。
   指摘が返ってきたら、**このエージェント自身はファイルを編集しないため、指摘の適用は呼び出し元(自分)が行う**。
   全指摘に対応し終えてから commit する。指摘ゼロでも、実行したこと自体を進捗として一言報告する。
6. **commit & push**（作業ブランチ）。

**一時停止して確認する判断点（ここだけは自動化しない）**:
- 長い禅語でカバーの字組みが崩れる場合（都度判断）。
- 事実関係が不確かで断定できない場合（捏造しない・要確認として相談）。
- 既存記事とテーマ/切り口が重複する疑いがある場合。
- `status`（公開状況）・`published_url` はオーナー確認事項として空のまま残す。

## ボリューム目安（実証済み）

| 版 | 目安 | 備考 |
|---|---|---|
| 日本語 | **~1,900〜2,100 字**（実質） | 基準サンプル `note_02_阿吽.md` = 2,276 字 |
| 英語（Medium） | **~720〜750 words** | CLAUDE.md の 700〜1,500 words の範囲内で、厚めのサンプルに合わせる |

> ⚠️ **この目安は下限を守るためのものであり、上限に収めるための目安ではない**（オーナー指示・2026-08-09）。
> 事実確認・誠実な断り・重複回避などに必要な記述を、目安に収めるために削ってはいけない。
> 上振れ（CLAUDE.md の上限 EN 1,500 words 以内で）は許容する。**足りない（目安を下回る）ことのほうが問題**。
> 執筆時に語数/字数が目安を超えていても、内容を削ってレンジに合わせ込む作業はしないこと。

- 語数・字数は**コードで計測**する（暗算しない）:
  ```bash
  # 英語（語数）
  python3 -c "import sys,re;t=open(sys.argv[1]).read();print('words:',len(re.findall(r\"[A-Za-z']+\",t)))" article.md
  # 日本語（おおよその文字数・空白/改行除く）
  python3 -c "import sys,re;t=open(sys.argv[1]).read();print('chars:',len(re.sub(r'\s','',t)))" article.md
  ```

## JA の敬体/常体チェックは目視だけでなくコードでも行う（2026-08-17〜）

bashoan の初回執筆で、目視レビューだけでは常体（だ・である調）の文末が3箇所（「心が波立つこともない。」
「食事を運んでくる。」「季節がめぐる。」）見落とされ、後日のオーナー改訂レビュー時に発見された。
語数/字数と同様、**register の一貫性も執筆直後にコードでチェックする**。

```bash
python3 -c "
import re
t = open('article.md').read()
body = t.split('-->')[1]  # note投稿手順コメントの後ろ
lines = [l for l in body.split(chr(10)) if l.strip() and not l.startswith(('#','*','＊','──','【','-'))]
polite = ['です','ます','でした','ません','でしょう','ください','なさい','んです','のです','のでしょう','ました','ましょう','ますか','でしたか','ですか']
for l in lines:
    for s in re.split(r'(?<=。)', l):
        s = s.strip()
        if not s or not s.endswith('。'): continue
        core = s[:-1]
        if any(core.endswith(p) for p in polite): continue
        if core.endswith('か') or '」' in s[-3:] or '』' in s[-3:] or core.endswith(('＊1','＊2','＊3')): continue
        print(repr(s))
"
```
出力される行は、(a) 引用符内の登場人物の発話（例:「〜のようだ。）、(b) 脚注番号での体言止め導入（例: 「〜X＊1。」）、
(c) 「〜か。」型の疑問文の断片 は既存の許容パターンなので除外してよい。それ以外はすべて常体の混在＝要修正。

## 構成の型（実証済み）

サンプルに倣い、以下の流れで書く。

1. **フック** — 具体物・意外性で引き込む
2. **由来の深掘り** — 語の出自・背景
3. **史実性への誠実な言及** — 事実と推測を区別する（下記「史実性の扱い」）
4. **文化的具体物** — 情景を1つ（例: 茶室の一輪挿し／達磨の掛け軸／金閣寺・鏡湖池）
5. **仕事への応用** — 読者の実務に接続
6. **自分の内側への応用** — 内面・習慣への接続
7. **詩的な締め** — 余韻を残す
8. **出典リスト** — 参照元を簡潔に列挙

## 史実性の扱い（重要）

禅語には**厳密には禅宗発祥でない語・出典が確実でない語**がある。断定せず、事実と解釈を分ける。

| 語 | 注意点 |
|---|---|
| 拈華微笑（ねんげみしょう） | 出典は偽経とされる |
| 達磨の言葉 | 解釈が 2 通りある |
| 鏡花水月 | 禅語ではなく**詩論由来**。鏡湖池との直接的な語源関係は確信度が低い |
| 一華開五葉 | 密教／詩論由来の語も含まれ、厳密には禅宗発祥でないものがある |

- 確信度の低い接続には「ここは私の解釈です」に相当する断りを本文に**地の文で**溶かし込む。
- カバー上の「禅語」ラベルは雨シリーズと同じ運用に合わせているが、上記の通り厳密には
  禅語でない語もある点は本文で明記する。

  縦 1 列 5 字でも 1280×720 に収まることを確認済み。）
- カバー生成スクリプトはリポジトリ内 [`../tools/build_covers.py`](../tools/build_covers.py)。
  `python3 tools/build_covers.py <slug>` で再生成（無指定で全件、`COVER_OUT_DIR` で出力先上書き）。
  依存: numpy / scipy / Pillow、フォント: `NotoSerifCJK-Black.ttc`。字数に応じ字サイズを自動調整するため、
  **縦 1 列のまま任意字数に対応**（長い禅語もカバーは正式名のまま。都度、崩れれば字サイズ/字間で調整）。
